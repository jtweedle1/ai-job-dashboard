Do NOT add "use client" directive — this is a plain TypeScript module, not a React component. It will only be imported from client components that already have "use client".

Import: import { auth } from "@/lib/firebase"; (the client Firebase instance that has getAuth state)
Import: import type { RequestInit } from "next/dist/server/web/spec-extension/request"; — actually, use the standard browser RequestInit type. In TypeScript with "lib": ["dom"] or Next.js, RequestInit is available globally. Do not import it explicitly.

Export a single async function:

  export async function authedFetch(
    url: string,
    options: RequestInit = {}
  ): Promise<Response>

Implementation:
1. Get the current user from auth.currentUser (the Firebase Auth instance exported from lib/firebase.ts).
2. If auth.currentUser is null, throw new Error("authedFetch called without authenticated user").
3. Get the ID token: const idToken = await auth.currentUser.getIdToken().
4. Merge the Authorization header into the existing headers:

   const headers = new Headers(options.headers);
   headers.set("Authorization", `Bearer ${idToken}`);
   if (!headers.has("Content-Type") && options.body) {
     headers.set("Content-Type", "application/json");
   }

5. Return fetch(url, { ...options, headers }).

This helper:
- Never puts uid in the body (callers are responsible for removing uid from their payloads)
- Always attaches a fresh ID token (tokens expire after 1 hour; getIdToken() refreshes automatically)
- Preserves all other options (method, body, signal, etc.)

TypeScript: auth is the Firebase Auth instance. Import from "@/lib/firebase":
  import { auth } from "@/lib/firebase";

Check lib/firebase.ts to confirm auth is exported (it should be based on ARCHITECTURE.md describing lib/firebase.ts as the client SDK providing auth).

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client components→API routes | Client components now attach ID tokens; the server verifies them |
| Firebase Auth token refresh | getIdToken() auto-refreshes; tokens are short-lived (1 hour) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01 | Spoofing | Client fetch calls — uid previously sent in body | mitigate | authedFetch replaces uid body param with server-verified Authorization header token |
| T-03-02 | Information Disclosure | authedFetch calling getIdToken() — token in memory | accept | Token is short-lived (1 hour), auto-refreshed by Firebase SDK, never stored in localStorage |
| T-03-03 | Denial of Service | authedFetch throwing on null auth.currentUser | accept | All pages are behind AppShell auth guard — authedFetch is only called when user is authenticated |
| T-03-SC | Tampering | npm installs | accept | No new npm packages introduced in this plan |
</threat_model>
